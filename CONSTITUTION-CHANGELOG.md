# CONSTITUTION-CHANGELOG.md

Dated history of amendments to [CONSTITUTION.md](CONSTITUTION.md): what changed and why. This file is a record, not a source of requirements — **the current rules are in `CONSTITUTION.md` alone**, and a reader (human or agent) does not need this file to know what must be true today. Consult it only to understand why a clause exists or how it got to its present form.

Append a new entry for every added or changed clause (see `CONSTITUTION.md` §10). Entry IDs are `YYYY-MON-DD-NNN`. Do not reference issue or pull-request numbers; state the reason in the entry itself.

- `2026-JUL-04-001` — Initial constitution: WCAG AA, no-JS-except-theme-switcher, and the terminus compatibility pinning strategy established. Fonts and design tokens frameworks established; specific typeface pairings and presentation styles deferred to prototyping.
- `2026-JUL-04-002` — Clarified §2 (JavaScript): the theme-switcher exception scopes narrowly to terminus's `js/theme-switcher.js`, not to terminus's JS footprint generally. Reason: the terminus compatibility audit (pinned snapshot `aa8d8b67f9ab69ae48e1405f96e152d41f03e0ed`) found terminus ships three additional JS features (popover auto-close, copy-to-clipboard, KaTeX rendering) beyond the theme switcher, which the original "equivalent in scope to terminus's own implementation" wording could be misread as endorsing. No change to the substantive rule (still zero JS except the switcher) — wording only.
- `2026-JUL-04-003` — Added §5 Layout grid system: every preset presentation style must be built on a 12-column responsive CSS grid, with no per-style opt-out. Reason: requested as a cross-cutting structural constraint (not a per-style choice) at the start of 'scholarly' style prototyping, so all five presets stay visually and structurally consistent at the grid level regardless of typography/colour differences. Renumbered §§5–7 to §§6–8 accordingly and fixed a stale §6 cross-reference in the intro (was pointing at Design tokens instead of Amendments).
- `2026-JUL-04-004` — Restructured §6 (Presentation styles) and §7 (Design tokens) into a two-level **group + variant** model: the 5-preset cap now applies to top-level groups (e.g. `scholarly`, `creative`, `engineering`), each of which may contain multiple fully-specified variants selected via a second config key (`extra.presentation_variant`), with one variant designated default per group. Reason: 'scholarly' prototyping produced five genuinely distinct, viable variants; flattening them into five separate top-level presets (`scholarly-01`...`scholarly-05`) would have consumed the entire 5-preset budget on one look-and-feel family, leaving no room for the other groups planned (`creative`, `engineering`, etc.). Design tokens now live one file per group (`specs/design-tokens-<group-name>.md`) with a section per variant, rather than one file per flattened style. No change to the substantive per-variant requirements (WCAG AA, font specification, 12-column grid, light/dark mode) — all now explicitly apply per variant rather than per top-level style.
- `2026-JUL-04-005` — Added §6 Navigation: the main nav must collapse into a disclosure/hamburger pattern below a breakpoint, implemented without JavaScript (native `popover`/`popovertarget`, `<details>`/`<summary>`, or checkbox-hack — never terminus's own JS auto-closer), with no per-style or per-variant exception. Reason: auditing the scholarly/creative style tiles found none of the ten prototype navs had a working collapse mechanism at all — they only looked fine at phone width because the sample menus happened to be short, which would silently break (horizontal overflow, violating §5) the moment a real site used more or longer menu items. Renumbered §§6–8 to §§7–9 accordingly; added a corresponding "must independently satisfy" reference in §7 (Presentation styles) and a nav-breakpoint token bullet in §8 (Design tokens).
- `2026-JUL-04-006` — Added §9 Brand identity: the theme must use the approved Tapestry logo (the "woven monogram" mark), rendered via `currentColor`, spec frozen in `specs/brand-logo.md`. Reason: the logo went through five prototyped concepts and two rounds of refinement (icon merged into the wordmark as the literal "t"; wordmark converted from live text to true vector outlines extracted from Space Grotesk Bold, so it no longer depends on the font loading) and is now approved — this closes out that design decision the same way approved design tokens get frozen into their own doc. Renumbered §9 (Amendments) to §10.
- `2026-JUL-04-007` — Pinned the Zola version to `0.22.1` in §3 (Terminus compatibility). Reason: CLAUDE.md's build-command checklist already instructed confirming the installed Zola version against a pin in this file, but no such pin existed yet — a dangling instruction with nothing to point at. `0.22.1` was chosen because it satisfies both terminus's own `min_version = "0.22.0"` and the Zola `0.21.0`+ requirement for GitHub-style alerts already relied on in the compat contract.
- `2026-JUL-04-008` — Clarified §2 (JavaScript): Tapestry's theme switcher is functionally narrower than terminus's — light/dark toggle only, not terminus's 13-scheme (`color_scheme`) picker. Reason: flagged as a deliberate break from terminus worth recording explicitly, since colour identity in Tapestry comes entirely from the presentation style group/variant (§7, §8) rather than from a separate scheme-selection control, and the earlier "equivalent in scope to terminus's own `js/theme-switcher.js`" wording could otherwise be misread as endorsing terminus's full multi-scheme picker behaviour. Added the corresponding deviation note to `specs/terminus-compat-contract.md` §9 (new section) and annotated the `color_scheme`/`color_scheme_switcher` rows in its §3 table. No change to any other substantive rule.
- `2026-JUL-04-009` — Added a theme-wide default and terminus-migration invariant to §7 (Presentation styles): when `extra.presentation_style` is unset or invalid, Tapestry defaults to the `scholarly` group with `contemporary-research-lab` as its default variant, unconditionally — and any leftover terminus-only keys (`extra.color_scheme`, `extra.color_scheme_switcher`) on a migrating site are inert and MUST NOT be mapped into an equivalent style/variant. Reason: closes an open question from the group+variant model (§7 already required each group to name a default variant, but never named the theme's own default *group*, nor stated what happens to a terminus site's leftover `color_scheme` config when `theme` is flipped to `tapestry` with no new keys added yet) — without this, behaviour on migration would be undefined. Cross-referenced from the corresponding migration-behaviour note added to `specs/terminus-compat-contract.md` §9.
- `2026-JUL-04-010` — Added a frozen maximum content width of 1200px to §5 (Layout grid system), shared across every group/variant, and fixed a stale `(see §7)` cross-reference in the same section (should have read §8, Design tokens — a leftover from the §5/§6/§7 renumbering in entry 003). Reason: during first-pass implementation of the `scholarly` group, the ported terminus base styles left the page body capped at terminus's own narrow ~864px `layout-center` width with no explicit Tapestry-specific override, which risked silently reproducing terminus's narrow terminal-column aesthetic instead of the wide editorial layout already prototyped in `prototypes/style-tiles/` and proven at 1200px in `prototypes/spikes/responsive-grid-spike.html`. Made explicit and frozen so no future group/variant can silently narrow the layout back down.
- `2026-JUL-05-001` — Amended §2 (JavaScript): added a **second** sanctioned JS exception for client-side KaTeX rendering, equivalent in scope to terminus's own `js/katex.min.js`, alongside the theme switcher. Reason: the build-time KaTeX pre-rendering pipeline adopted under the original §2 (a Node script running `katex.renderToString()` before `zola build`, see the now-removed `specs/katex-build-pipeline.md`) was real and functional, but only activated through a separate `npm run build`/`npm run serve` entry point — bare `zola build`/`zola serve` (the obvious, first-reached-for commands, and still what terminus itself needs nothing more than) left KaTeX-enabled content showing raw unrendered `$...$` source, a regression from terminus's own out-of-the-box behaviour that undermined the whole point of terminus compatibility. Explicitly decided to accept client-side KaTeX JS as a second exception rather than keep patching the build-time approach's discoverability. The build-time pipeline (`scripts/render-katex.js`, `package.json`, `package-lock.json`, `specs/katex-build-pipeline.md`) was removed as superseded, not left as unused dead weight. `themes/tapestry/static/js/katex.min.js` is now vendored verbatim from terminus, loaded identically to terminus's own `extra.katex` gate.
- `2026-JUL-05-002` — Amended §2 (JavaScript): added a **third** sanctioned JS exception, a presentation style/variant switcher, gated by `extra.presentation_style_switcher` (default `false`). Reason: requested as a new, wholly Tapestry-original feature (no terminus equivalent) — a disclosure menu next to the theme switcher listing every implemented `<style>/<variant>` combination, letting a visitor preview a different look live without a page reload. This is inherently a runtime, client-side operation (swapping the `data-style`/`data-variant` attributes `_variants.scss` already keys its custom properties off) with no static/no-JS equivalent, unlike the nav collapse or grid, so a third JS exception was the only option rather than a CSS-only reimplementation. Opt-in (default `false`) rather than unconditional like the theme switcher, since it's a nice-to-have preview tool rather than baseline site functionality. `specs/terminus-compat-contract.md` §7's "exactly two JS files" count updated to three accordingly.
- `2026-JUL-05-003` — Added a bullet to §5 (Layout grid system): the single-article template's columns 9–12 sidebar region is content-driven, not unconditionally reserved — it renders only when there's an automatic heading TOC (pages with ≥2 headings) and/or custom content via `page.extra.sidebar` (a path to a colocated Markdown snippet, loaded with `load_data(format="plain") | markdown`), with `page.extra.sidebar = false` forcing it off entirely; the article body MUST reclaim the full 12 columns whenever no sidebar renders. Reason: `specs/design-tokens-scholarly.md` had frozen a 1–8/9–12 article/sidebar column split for every scholarly variant, but no template ever actually rendered anything into the sidebar region — every single-article page (e.g. `content/about.md`, blog posts) permanently lost columns 9–12 to empty reserved space, making them look narrower and left-aligned relative to the front page and section listings (which aren't subject to that split). Rather than silently widen the article back to 12 columns (which would have contradicted the frozen design-tokens doc) or silently leave the empty reservation in place, the sidebar was implemented for real, keyed off content presence so the reservation only exists when it's earning its keep. `specs/design-tokens-scholarly.md`'s five per-variant "Grid breakpoints & column spans" tables and `specs/terminus-compat-contract.md` §5 (page-level front matter) were updated to match.
- `2026-JUL-06-002` — Amended §2 (JavaScript): switched KaTeX CSS from `css/katex.min.css` (`font-display: block`, the default terminus-vendored file) to `css/katex-swap.css` (KaTeX's own officially published `font-display: swap` variant, sourced from the same KaTeX 0.16.47 release). Reason: KaTeX ships two CSS variants — the default uses `font-display: block` intentionally (to prevent layout shift from fallback fonts during math rendering), while `katex-swap.css` provides `font-display: swap` for those who prefer it — a distinction the KaTeX maintainers explicitly document and support. The §4 mandate that all `@font-face` declarations MUST use `font-display: swap` applies equally to KaTeX fonts; using the official swap variant satisfies §4 without hand-patching a third-party file, and keeps the vendored CSS updateable as a clean upstream artefact. Font paths were adapted from KaTeX's CDN-layout (`fonts/`) to Tapestry's self-hosted layout (`../fonts/katex/`) — the only local modification. `base.html` updated to load `css/katex-swap.css`; `<link rel="preload">` hints for `KaTeX_Main-Regular.woff2` and `KaTeX_Math-Italic.woff2` added inside the KaTeX gate to reduce the critical request chain from 3 hops to 2.
- `2026-JUL-06-001` — Rewrote §4 (Fonts) to mandate **self-hosting** of all web fonts as WOFF2 files committed under `themes/tapestry/static/fonts/<variant-name>/`, removing all language about Google Fonts CDN as a delivery mechanism. Reason: the `contemporary-research-lab` variant (the only implemented variant) was converted to self-hosted fonts — Fraunces, Inter, and Space Mono vendored as latin + latin-ext WOFF2 pairs — eliminating the render-blocking Google Fonts CDN stylesheet and removing a third-party network dependency from every page load. All future variants will follow the same pattern (Google Fonts used as an upstream source to download from, never as a live CDN). The new §4 additionally mandates: latin + latin-ext subsets by default, variable fonts preferred, `font-display: swap` on all `@font-face` declarations, `<link rel="preload">` hints for the primary body and heading fonts per variant, and the path-identity requirement between preload `href` and `@font-face src` (no `cachebust=true`, to prevent the browser fetching the file twice). Metric-adjusted `@font-face` fallback stacks (using `size-adjust`, `ascent-override`, `descent-override`, `line-gap-override`) are retained in `_fonts.scss` to reduce CLS during font swap.
- `2026-JUL-06-003` — Amended §4 (Fonts): updated the self-hosted font path pattern from `themes/tapestry/static/fonts/<variant-name>/` to `themes/tapestry/static/fonts/<style-name>/<variant-name>/`. Reason: with all five scholarly variants now having their fonts self-hosted, the flat `fonts/<variant-name>/` layout would have no group context — `fonts/classic-ivy/` and `fonts/contemporary-research-lab/` are meaningless without knowing they both belong to `scholarly`. The two-level `fonts/<style>/<variant>/` path mirrors the two-level `extra.presentation_style`/`extra.presentation_variant` config model and makes it unambiguous which group a set of fonts belongs to. Existing `contemporary-research-lab` fonts moved from `fonts/contemporary-research-lab/` to `fonts/scholarly/contemporary-research-lab/`; all `@font-face` src paths in `_fonts.scss` and preload hrefs in `base.html` updated accordingly. The remaining four scholarly variants (classic-ivy, nordic-minimalist, dark-academia, scientific-journal) had their fonts vendored at the same time under `fonts/scholarly/<variant-name>/`, completing the self-hosting requirement for the entire scholarly group and removing the last CDN font references from `base.html` and `presentation-style-switcher.js`.
- `2026-JUL-10-001` — Amended §2 (JavaScript): the presentation style/variant switcher's disclosure menu must be a two-level, grouped accordion (one expandable entry per style group, revealing that group's variants) rather than a flat listing of every `<style>/<variant>` combination — mandatory at any group/variant count, with the full interaction spec frozen in the new `specs/presentation-style-switcher.md`. Reason: with the `creative` group landing in the prior commit (10 combinations shipped, `scholarly` + `creative` × 5 variants each) and a cap of 5 groups each free to define as many variants as prototyping produces (§7), a flat list was already borderline and would become unusable well before the cap is reached — the same "must not silently rely on there being few enough items" concern §6 already raised about nav collapse applies here. This is a genuine constitution-level requirement, not a design-token one: it's a cross-cutting structural mandate that must hold regardless of which/how many groups and variants exist, the same category as §5 (grid) and §6 (nav collapse), not a per-variant colour/type/spacing choice (§8). The accordion mechanic itself is specified as native HTML (`<details name="...">` exclusive groups), so it does not draw on or expand the §2 JS-exception budget — only variant *selection* still requires the already-sanctioned switcher JS.
- `2026-JUL-11-001` — Added a "Decorative background pattern (optional, per variant)" bullet to §8 (Design tokens): `--pattern-bg-image` / `--pattern-bg-size` custom properties, CSS-only, with a documented contrast ceiling (≤0.15 alpha for full-bleed line/dot-grid patterns, or exposed-background-area headroom for sparse point decorations like a starfield). Reason: 8 of the 25 approved style tiles under `prototypes/style-tiles/` (`collective-01-cartographers-atlas`, `collective-02-ledger-index`, `creative-02-editorial-zine`, `natural-01-celestial-observatory`, `natural-04-chalkboard-proof`, `natural-05-quantum-circuit`, `precision-01-blueprint-drafting`, `precision-04-biomedical-diagnostics`) already used a pure-CSS `background-image` gradient/pattern (graph-grid lines, dot grids, a starfield, a repeating radial contour texture) as part of their approved visual identity, but neither `specs/design-tokens-<group>.md` nor the shipped `_variants.scss` ever captured or implemented it — those 8 variants have been rendering with a flat background only, silently dropping part of their approved design since implementation. Explicitly scoped as optional (not every variant needs the motif, and mandating one everywhere would force it onto variants like `scholarly`/`contemporary-research-lab` that were never designed with one) per the same "cap applies to what's actually used, not everything a doc could support" reasoning as the optional article/sidebar region (§5, `2026-JUL-05-003`). The contrast ceiling closes the obvious accessibility risk of a decorative gradient eroding body-text contrast below the §1 AA floor.
- `2026-JUL-16-001` — Narrowed, but did not eliminate, a previously undocumented §1 (Accessibility) regression: the header logo/home link — `themes/tapestry/sass/css/_header.scss`, shared unmodified across every group/variant per §9 — was keyboard-unreachable (SC 2.1.1/2.4.7) on every page, because a three-level `display: contents` flattening (`.header-logo-container` > `a` > `.logo`) removed the anchor from Chromium's render/focus tree entirely. That flattening exists to fix a genuine 0x0 rendering collapse, but the collapse only ever affected the raster/vector `extra.header_logo` fallback tier (`.logo-img`) — the default inlined-SVG brand mark and the `extra.header_title` plain-text fallback never needed it, per the investigation recorded inline in `_header.scss`. Scoped the flattening to only apply when a `.logo-img` is present (`.header-logo-container:has(.logo-img)`), verified via real Tab-key traversal (not just `.focus()`, which does not reliably reproduce Chromium's `:focus-visible`/tab-order behaviour) across all three `logo.html` fallback tiers. Reason this is recorded here rather than left as the sole inline SCSS comment it previously was: that comment referenced a plan doc under `docs/superpowers/plans/`, a gitignored, non-persisted scratch directory — the only durable trace of this issue was at risk of being lost entirely. **Residual, still-open gap:** sites that set `extra.header_logo` still hit the original keyboard-unreachable regression on that link specifically; every CSS-only alternative tried so far (documented in `_header.scss`) either reproduces the 0x0 collapse or requires giving the logo slot a fixed envelope box independent of the image's aspect ratio, a trade-off not adopted without explicit sign-off. This is theme-wide shared infrastructure, not a per-group concern — fixing it (or accepting the fixed-envelope trade-off) closes the gap for every group/variant at once, not one at a time.
- `2026-JUL-16-002` — Added an "Alert colours are shared and mode-scoped, not per-variant" bullet to §8 (Design tokens), documenting the existing (previously undocumented) `--alert-<type>-border`/`-bg`/`-code` token set: one shared value per mode across every group/variant, deliberately excluded from the per-variant token list and from `specs/design-tokens-<group-name>.md`, plus the requirement that these tokens clear §1's AA floor against every group/variant's composited alert background simultaneously, and the three-copy-in-sync requirement (`:root`, the `prefers-color-scheme: dark` media query, and the `html[data-color-mode]` theme-switcher overrides). Reason: while fixing the collective-group a11y sweep, these tokens had to be darkened a second time because the first darkening (done earlier for scholarly) only cleared scholarly's composited backgrounds, not collective's warmer `strata-geology` background — and a second, out-of-sync copy of the same tokens in the `html[data-color-mode='light']` override block was found still holding the pre-fix values, which was the reason the first attempt at the second darkening silently didn't take effect in tests. Both facts — that the tokens are intentionally shared rather than per-variant, and that they exist in three places that must stay in sync — were previously recorded only as inline SCSS comments in `_variants.scss`, which is exactly how the three-copy duplication went unnoticed. No change to any other substantive rule; this section only makes an existing, load-bearing design decision and its accompanying accessibility invariant explicit and discoverable.
- `2026-SEP-29-001` — Bumped the pinned Zola version in §3 from `0.22.1` to `0.23.6`. Reason: Zola 0.23 bundles Tera v2, a from-scratch, non-backward-compatible rewrite of the template engine — macros and `{% import %}` are removed entirely, replaced by a "hygienic" component system (`{% component %}`/`{{ <name .../> }}`) with **no implicit access to ambient context** (`page`, `section`, `config`, `lang`, `taxonomy` must be passed explicitly by the caller); undefined variables now error at render instead of failing silently; several filters/functions were renamed or removed (`concat`/`slice` replaced by array-spread and native slicing, `trim_end_matches`/`trim_start_matches` → `trim_end`/`trim_start`, `linebreaksbr` → `newlines_to_br`, string tests now require kwargs). Additionally, and not anticipated by the original issue scope, **Zola 0.23 removed the shortcode subsystem entirely** — every shortcode under `themes/tapestry/templates/shortcodes/` was rewritten as a Tera v2 component, and every shortcode invocation across `content/**/*.md` was rewritten from the old `{% name(args) %}`/`{{ name(args) }}` syntax to the new `{% <name attr="x"> %}...{% </name> %}`/`{{ <name attr="x" /> }}` syntax — including replacing the old `{{/* ... */}}` literal-escaping trick in documentation code-fences (no longer functional under v2's whole-file template compilation) with `{% raw %}...{% endraw %}`. The recursive TOC macro was extracted out of `page.html` into a standalone `macros/toc.html`, since v2's global component registration removes the `self::`-driven reason it had to be co-located with the entry template. The same change reconciled the CI workflows (`.github/workflows/`) and the Netlify pin onto `0.23.6`, re-diffed `specs/terminus-compat-contract.md` against the rewritten components (no drift beyond the documented invocation-syntax note), and re-ran the full `tests/visual-a11y` suite across every presentation style group/variant on `0.23.6`.

Reason: `CONSTITUTION.md` is read in full, including by agents that load it as standing context, and should describe only what must be true *now*. Interleaving the history of how each clause came to be (superseded values, removed pipelines, bumped pins) made the current rules harder to read and let stale historical claims sit next to live ones. Entries are unchanged apart from `2026-SEP-29-001`, whose reference to a tracking issue and its statement of work then still outstanding (CI pins, compat-contract re-diff, test re-run — all since completed) were replaced with the facts as they now stand. - `2026-OCT-04-001` — Reframed §3 from "Terminus compatibility" to "Terminus lineage and carried-over features", and removed every claim that Tapestry is backward-compatible with terminus. Reason: the pinned terminus snapshot targets Tera v1, and Tera v2 (adopted under `2026-SEP-29-001`) removed macros and `{% import %}` (replaced by components) and removed shortcodes entirely, so terminus templates, template overrides and macro imports cannot run on Tapestry, and terminus-style shortcode invocations in content must be rewritten. A compatibility guarantee was therefore untrue. What is retained: the pinned snapshot, the frozen `specs/terminus-compat-contract.md` (now describing carried-over parameters and rendered output rather than a compatibility promise; filename unchanged), the live-usage hard floor, and the Zola `0.23.6` pin. Added the explicit statement that Zola releases before `0.23.0` cannot build Tapestry. The terminus-derivation attribution (`theme.toml` `[original]`, README credits) is unaffected.
